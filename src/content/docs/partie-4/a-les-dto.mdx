En partie 3, `POST /api/villages` acceptait `@Body() village: Village` — mais rien ne garantissait que le corps envoyé ressemblait vraiment à un `Village`. Un **DTO** (*Data Transfer Object*) décrit la forme des données attendues à l'entrée d'une route.

```ts title="src/villages/dto/creer-village.dto.ts"
export class CreerVillageDto {
	nombreDeJoueurs: number;
	rolesEnJeu: string[];
}
```

```ts title="src/villages/villages.controller.ts" {2,7}
import { Body, Controller, Post } from '@nestjs/common';
import { CreerVillageDto } from './dto/creer-village.dto.js';

@Controller('api/villages')
export class VillagesController {
	@Post()
	creer(@Body() dto: CreerVillageDto) {
		// dto.nombreDeJoueurs et dto.rolesEnJeu sont typés
	}
}
```

C'est déjà mieux qu'un `any` implicite : ton éditeur connaît `dto.nombreDeJoueurs`, et une faute de frappe sur son nom est détectée à la compilation. Mais ce n'est qu'une **promesse TypeScript** — au moment où `tsc` a fini son travail, elle disparaît. Rien n'empêche encore un client d'envoyer `{ "nombreDeJoueurs": "beaucoup" }`, une chaîne au lieu d'un nombre : à l'exécution, personne ne vérifie. La section b comble ce trou.
