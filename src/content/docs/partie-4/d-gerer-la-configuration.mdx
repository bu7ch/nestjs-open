Depuis la partie 3, `main.ts` lit `process.env.PORT` directement. Ça fonctionne, mais rien ne dit ce que ton application attend comme variables d'environnement, ni ne prévient si l'une d'elles manque. `@nestjs/config` structure ça.

```bash
npm install @nestjs/config
```

```bash title=".env"
PORT=3000
NOMBRE_MAX_VILLAGES=50
```

`ConfigModule.forRoot({ isGlobal: true })` lit ce fichier au démarrage, et rend `ConfigService` injectable partout dans l'application :

```ts title="src/app.module.ts" {2,6}
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';

@Module({
	imports: [ConfigModule.forRoot({ isGlobal: true }), /* … */],
})
export class AppModule {}
```

```ts title="src/main.ts" {3,7,8}
import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { AppModule } from './app.module.js';

async function bootstrap() {
	const app = await NestFactory.create(AppModule);
	app.useGlobalPipes(new ValidationPipe());
	const config = app.get(ConfigService);
	await app.listen(config.get('PORT') ?? 3000);
}
await bootstrap();
```

`ConfigService` s'injecte aussi dans un service, exactement comme n'importe quel autre provider — plus besoin de toucher à `process.env` où que ce soit dans ton code :

```ts title="src/villages/villages.service.ts" {3,6}
@Injectable()
export class VillagesService {
	constructor(private readonly config: ConfigService) {}

	creer(dto: CreerVillageDto) {
		const maximum = this.config.get<number>('NOMBRE_MAX_VILLAGES');
		// …
	}
}
```

## Valider les variables d'environnement

Un `.env` incomplet plante silencieusement plus tard, au premier `undefined` inattendu — bien après le démarrage. L'option `validate` de `ConfigModule.forRoot` vérifie tout **avant**, avec les décorateurs de la section b :

```ts title="src/config/variables-environnement.ts"
import { IsNumber, Min } from 'class-validator';
import { plainToInstance } from 'class-transformer';
import { validateSync } from 'class-validator';

class VariablesEnvironnement {
	@IsNumber()
	PORT: number = 3000;

	@IsNumber()
	@Min(1)
	NOMBRE_MAX_VILLAGES: number;
}

export function validerEnvironnement(config: Record<string, unknown>) {
	const validees = plainToInstance(VariablesEnvironnement, config, { enableImplicitConversion: true });
	const erreurs = validateSync(validees, { skipMissingProperties: false });
	if (erreurs.length > 0) throw new Error(erreurs.toString());
	return validees;
}
```

```ts title="src/app.module.ts" {2}
ConfigModule.forRoot({ isGlobal: true, validate: validerEnvironnement }),
```

Retire `NOMBRE_MAX_VILLAGES` du `.env`, et le serveur refuse de démarrer — au lieu de démarrer normalement et d'échouer beaucoup plus tard, en pleine requête.
